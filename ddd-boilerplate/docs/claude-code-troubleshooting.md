## コンテキストオーバーフロー

### 症状

```
API Error: 400 Input is too long for requested model.
```

または

```
⚠ Large MCP response (~3.8m tokens), this can fill up context quickly
```

### 原因

MCP の `filesystem` サーバーの `directory_tree` コマンドが、`node_modules` などの巨大なディレクトリを含むプロジェクト全体をスキャンし、数百万トークンのレスポンスを生成した場合に発生します。

### 影響

- 現在のセッションが使用不能になる
- 以降の API 呼び出しが全て失敗する
- セッション内での回復は不可能

### 解決策

**即時対応:**
1. 現在のセッションを終了（`/clear` または新しいチャットを開始）
2. 新しいセッションを開始
3. 問題の操作を避けて再実行

**予防策:**
- `directory_tree` MCP コマンドを使用しない
- 代わりに Cursor 組み込みの `LS` ツールを使用
- `Glob` ツールでパターンマッチング検索を行う

## MCP ツールの問題

### 危険なツール一覧

| ツール | 問題 | 代替案 |
|--------|------|--------|
| `filesystem - directory_tree` | 巨大なレスポンスを返す可能性 | `LS` ツール |
| `filesystem - list_directory "/"` | ルートディレクトリは危険 | 特定のサブディレクトリを指定 |

### 安全なファイル探索パターン

```markdown
# ❌ 避けるべきパターン
「プロジェクト構造を見せて」→ directory_tree を使う可能性

# ✅ 安全なパターン
「src ディレクトリの構造を見せて」→ 限定的なスコープ
「TypeScript ファイルを探して」→ Glob("**/*.ts")
「Entity クラスを探して」→ SemanticSearch
```

### MCP サーバー設定の改善

`.mcp.json` で `filesystem` サーバーを使う場合は、読み取り専用に制限することを推奨：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "./src"],
      "description": "File system access limited to src directory"
    }
  }
}
```

**注意:** ディレクトリを `./src` などに制限することで、`node_modules` がスキャンされることを防ぎます。

## パフォーマンスの問題

### 大きなファイルの読み取り

**問題:** 大きなファイル（数千行以上）を読み取ると、コンテキストを圧迫する

**解決策:**
```markdown
# 特定の行範囲のみ読み取り
Read ツール + offset/limit パラメータを使用

# または、Grep で必要な部分のみ検索
Grep ツールで関連コードを特定
```

### 多数のファイルを同時に読み取り

**問題:** 10個以上のファイルを同時に読み取ると、コンテキストが急速に埋まる

**解決策:**
- 必要なファイルを優先順位付けして読み取る
- 関連性の高いファイルから順に読む
- SemanticSearch で関連コードを事前に特定

## 回復手順

### セッションのリセット

1. **Cursor IDE の場合:**
   - 新しいチャットを開始
   - または `/clear` コマンドを使用

2. **Claude Code CLI の場合:**
   - `Ctrl+C` でセッションを終了
   - 新しいセッションを開始

### 作業の継続

セッションをリセットした後、以下の手順で作業を継続：

1. **コンテキストの再構築:**
   ```markdown
   @CLAUDE.md を読んでプロジェクトを理解して
   ```

2. **進捗の確認:**
   - 変更済みファイルを `git status` で確認
   - 未コミットの変更を保存

3. **安全な探索:**
   - `LS` ツールでディレクトリ構造を確認
   - `Glob` ツールで必要なファイルを特定

## よくある質問

### Q: なぜ directory_tree が危険なのですか？

A: `directory_tree` はディレクトリ内のすべてのファイルとサブディレクトリを再帰的にリストします。`node_modules` のような巨大なディレクトリが含まれている場合、数十万〜数百万のエントリが返され、コンテキストウィンドウを即座に使い果たします。

### Q: セッションを失った場合、作業は失われますか？

A: いいえ。ファイルへの変更はすでにディスクに保存されています。セッション履歴のみが失われますが、以下で確認できます：
- `git diff` で変更内容を確認
- `git status` で変更ファイルを確認

### Q: どのモデルでもこの問題は発生しますか？

A: はい。すべてのモデルにはコンテキストウィンドウの制限があります：
- Claude 3.5 Sonnet: 200K トークン
- Claude 3 Opus: 200K トークン
- GPT-4: 128K トークン

3.8M トークンはどのモデルの制限も超えています。
